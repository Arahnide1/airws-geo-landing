# Лендинги AiR

Статичные лендинги на общей дизайн-системе: HTML + CSS + JS. Формы отправляются через общий `send.php` в Битрикс24.

| Лендинг | Путь | Префикс целей Метрики |
|---|---|---|
| GEO-продвижение, вариант A | `/` (`index.html`) | нет |
| GEO-продвижение, вариант B (A/B-тест) | `/geo-b/` | `b_` |
| GEO-продвижение, вариант C (A/B-тест, контроль) | `/geo-c/` | `c_` |
| Контекстная реклама | `/context/` | `ctx_` |
| Контекстная реклама, вариант B | `/context-b/` | `ctxb_` |
| Контекстная реклама, вариант C | `/context-c/` | `ctxc_` |

## A/B-тест GEO
Вариант B отличается от A стилем (светлая прохладная палитра, кобальт и жёлтый маркер, шрифты Golos Text и Literata, свой `geo-b/style.css`) и структурой (первый экран — ответ нейросети с выделенным брендом, форма в одну строку, квиз в виде диалога, пример отчёта, сравнительная таблица цен, «что гарантируем и что нет»). Оффер, цены и кейсы одинаковые, чтобы тест сравнивал подачу, а не условия.

Как запускать: в Директе одинаковые объявления и таргетинги, трафик делится поровну между URL `/` и `/geo-b/`. Удобнее всего через «Эксперименты» в Директе (Яндекс Аудитории → эксперимент 50/50 → корректировки по сегментам) или двумя группами с одинаковыми настройками. Сравнивать конверсию в цели `lead` (A) и `b_lead` (B). Для значимого результата нужно порядка 100+ заявок суммарно или 2–4 недели трафика. В лиде Битрикс24 вариант виден по названию: «GEO-лендинг» или «GEO-лендинг B». У варианта B в лид также попадает результат квиза, если человек его прошёл.

Цели варианта B: те же, что ниже, с префиксом `b_`, плюс `b_quiz_start`, `b_quiz_done`, `b_quiz_cta`.

Вариант C — намеренно типовой лендинг «как у всех»: градиентный первый экран с формой справа, галочки, 6 карточек преимуществ с иконками, 5 шагов, баннер-призыв, кейсы карточками, 3 тарифа, отзывы, FAQ, форма на синем фоне. Шрифты Montserrat + Open Sans, свой `geo-c/style.css`. Нужен как контрольная группа: показывает, сколько дают нестандартная подача A и B по сравнению с шаблоном. Оффер, цены и кейсы те же. Отзывы в C демонстрационные, перед запуском заменить на реальные или убрать. Цели с префиксом `c_` (основная `c_lead`), плюс `c_cta_banner`. В Битрикс24 лид называется «GEO-лендинг C». При тесте трёх вариантов трафик делится на три равные части, и нужных заявок, соответственно, больше.

## Варианты лендинга контекста
Оффер, цены и кейсы (реальные, из документа «Кейсы: Контекстная реклама») одинаковые, отличаются идея, дизайн и порядок блоков.
- **A** (`/context/`) — в стиле airws.ru: демо рекламной выдачи, боли, аудит, кейсы карточками, калькулятор.
- **B** (`/context-b/`) — «куда уходит бюджет». Первый экран: заголовок с формой аудита и чек расходов за месяц с переключателем «Сейчас / После чистки». Светло-серая палитра, чёрный и сигнальный оранжевый, шрифты Unbounded + Manrope + JetBrains Mono. Дальше: 4 утечки бюджета, кейсы реестром на тёмном фоне, сроки диаграммой по дням, цены строками, оранжевый финал. Доп. цель `ctxb_receipt_toggle`. Цифры в чеке условные, это подписано.
- **C** (`/context-c/`) — «сколько заявок принесёт бюджет». Калькулятор и есть первый экран, бюджет из него попадает в лид. Тёмно-зелёная палитра с янтарным акцентом, шрифт Onest. Дальше: полоса аудита, кейсы во вкладках, этапы по дням с липкой колонкой преимуществ, два тарифа, FAQ в две колонки. Доп. цель `ctxc_case_tab`.

Основная цель для Директа: `ctx_lead`, `ctxb_lead`, `ctxc_lead` соответственно. В Битрикс24 лиды называются «Контекст-лендинг», «Контекст-лендинг B», «Контекст-лендинг C».

## Файлы
- `index.html` — GEO-лендинг
- `context/index.html` — лендинг контекстной рекламы (демо выдачи задаётся в `window.AIR_DEMO` внизу страницы)
- `assets/css/style.css` — общие стили (токены сняты с airws.ru) и блоки обоих лендингов
- `assets/js/main.js` — демо, анимации, калькулятор, цели Метрики, UTM, отправка форм. Настройки страницы берутся из атрибутов `<body>`: `data-landing`, `data-goal-prefix`, `data-endpoint`
- `send.php` — обработчик форм → Битрикс24 `crm.lead.add`. Название лида начинается с «GEO-лендинг» или «Контекст-лендинг»
- `config.example.php` — шаблон настроек. Скопировать в `config.php` и заполнить

## Запуск на хостинге
1. Залить папку целиком на хостинг с PHP 7.4+ и расширением curl, например на поддомен `promo.airws.ru` (тогда GEO будет в корне, контекст на `/context/`).
2. Создать в Битрикс24 (corp-airws.ru) входящий вебхук: «Разработчикам» → «Другое» → «Входящий вебхук», права **CRM**.
3. `cp config.example.php config.php` и вставить URL вебхука в `b24_webhook`.
4. Отправить тестовую заявку с каждого лендинга и проверить, что лид появился в CRM с UTM-метками.

Что попадает в лид: лендинг и тип формы, имя, телефон, сайт, тариф, способ связи, есть ли реклама сейчас и бюджет из калькулятора (контекст), UTM (source/medium/campaign/content/term), yclid, ClientID Метрики, страница и реферер.
Если Битрикс24 не ответил, заявка уходит письмом на `fallback_email`.

## Яндекс.Метрика
Счётчик **16999798**, тот же, что на airws.ru. Чтобы считать лендинги отдельно, заменить ID в `<head>` каждой страницы и в `main.js` (`YM_ID`).

Цели (тип «JavaScript-событие»). Для лендинга контекста те же цели создаются с префиксом `ctx_`: `ctx_lead`, `ctx_lead_audit` и т. д.

| Идентификатор | Когда срабатывает |
|---|---|
| `lead` | Любая успешная заявка (**основная цель для Директа**) |
| `lead_audit` | Заявка из формы лид-магнита (AI-срез / аудит рекламы) |
| `lead_lead` | Заявка из финальной формы |
| `lead_error` | Ошибка отправки |
| `form_start_audit`, `form_start_lead` | Начал заполнять форму |
| `cta_hero`, `cta_header`, `cta_mobile_bar`, `cta_hero_prices`, `cta_hero_calc` | Клики по CTA |
| `tariff_*` | Выбор тарифа (GEO: `base`, `optimal`, `complex`; контекст: `audit`, `base`, `optimal`) |
| `calc_use`, `calc_cta` | Калькулятор бюджета (контекст) |
| `phone_click`, `email_click`, `tg_click`, `max_click` | Контакты |
| `demo_tab` | Переключение вкладки в демо |
| `faq_open` | Открыт вопрос FAQ |
| `scroll_50`, `scroll_90` | Глубина скролла |

## Перед запуском рекламы
**GEO**
- Заменить демонстрационные кейсы на реальные или согласовать формулировки.
- Тарифы GEO согласованы: Базовый от 45 000 ₽, Оптимальный от 75 000 ₽, Комплексный от 100 000 ₽. Состав описан без количеств, точный объём фиксируется после AI-среза.
- Правки специалиста (ноябрь 2026) внесены во все три GEO-варианта: таблица «SEO и GEO», нейросети в порядке популярности (Алиса AI, ChatGPT, Google AI, Claude, DeepSeek), вместо скриншотов «точки роста», вместо техчасти и llms.txt — единые сведения о бренде, внешние источники с первого месяца, отчёт через AI Visibility, упоминания, цитирования и репутацию. Убраны «правки, которые можно сделать без нас» и фраза про «скрипты». Отчёт по каждому запросу в каждой нейросети оставлен: сервис мониторинга (Пиксель Тулс) это умеет. Пример отчёта в варианте B повторяет структуру настоящего отчёта сервиса: видимость, доля голосов, тональность, упоминания, позиции бренда и сайта, конкуренты, источники. Цифры в примере демонстрационные. GigaChat и Grok убраны из списка нейросетей: сервис их не отслеживает.
- Проверить обещание «AI-срез за 1 рабочий день».

**Контекст**
- Тарифы взяты со страницы airws.ru/services/reklama/context/. На ней указано и «от 18 000 ₽», и пакеты за 15 000 / 25 000 ₽. На лендинге стоят цены пакетов, нужно сверить.
- Кейсы (ноябрь 2026) заменены во всех трёх вариантах на шесть из документа «Кейсы: Контекстная реклама»: санаторий «Озеро Карачи», YANS, «Сфинкс», ROSA, «Анима», «Тайм Лизинг». Цифры только из документа, округлённые «~» убраны. Ссылок на полные кейсы нет, цель `case_open` больше не срабатывает. Графики «до и после», о которых просит комментарий в документе, пока не сделаны: картинки из документа недоступны.
- Ссылки на airws.ru убраны со всех шести лендингов (логотип больше не ссылка). Оставлены только ссылки на согласие на обработку персональных данных и политику конфиденциальности: они нужны по закону рядом с формой.

## Обновление стилей и скриптов
GitHub Pages кеширует файлы до 10 минут. После правок в `style.css` или `main.js` увеличьте версию `?v=` в подключении на обеих страницах.

## GitHub Pages
Версия на `*.github.io` нужна для показа и согласования. PHP там не выполняется, поэтому формы работают в демо-режиме: показывают «Заявка принята», но ничего не отправляют. Метрика на github.io и localhost не подключается. Для рекламы лендинги нужно залить на хостинг с PHP.

## Локальный просмотр
`python -m http.server 8765 --directory landing`. На localhost формы не отправляются в Битрикс: данные выводятся в консоль браузера.
